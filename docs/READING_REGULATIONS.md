# 규정 원문 열람

공개 첫 화면은 목차·본문·연결 규정으로 구성된 원문 열람 화면입니다. 기존 질문 검색은 `search.html`에서 계속 제공합니다. 정부 공식 서비스가 아니며, 수록 PDF와 자료 기준일 범위 안에서 열람합니다.

1. 법령·고시·SOP 분류 탭을 선택하고, 아래 문서 버튼과 적용 기준일을 선택합니다. 해당 날짜에 게시된 문서가 없으면 다른 버전을 임의로 대체하지 않습니다.
본문은 원문의 항·호·절차 번호를 기준으로 구획하며, PDF의 줄바꿈을 문장 단락 안에서 자연스럽게 표시합니다. SOP의 짧은 원문 머리말·쪽 표시는 접어서 확인합니다. 원문 문구는 요약하거나 수정하지 않습니다.

2. 본문 목차에서 조문 또는 SOP 절을 선택합니다. 목차 검색은 번호·제목을 대상으로 합니다. 원문 내용에 대한 검색은 상단의 질문 검색을 이용합니다.
3. 별표·서식은 별도의 목차에서 선택합니다. 파싱 가능한 별표에는 항목 선택을 제공합니다. 추출문과 함께 PDF의 표 배치·예외·공통 조건을 확인합니다. 조밀한 표의 텍스트를 재구성한 표로 오인하지 않도록 PDF를 우선 제공합니다.
4. PDF 쪽 목차에서는 표·그림·간지·공백을 포함한 모든 물리적 페이지를 열 수 있습니다. PDF 화면 열기는 선택 시에만 로드하며 새 창 링크도 제공합니다.
5. 본문의 인용 링크 또는 연결 규정에서 수록된 다른 조문·별표로 이동합니다. 자동으로 확정할 수 있는 인용 관계만 표시하며, 모든 위임 관계의 완전성을 보장하지 않습니다. 같은 주제의 SOP를 법적 위임 관계로 추정하지 않습니다.
6. 현재 항목 링크 복사로 문서·조문/절/별표/쪽·기준일이 포함된 주소를 공유합니다. 인쇄는 선택한 항목의 본문을 중심으로 제공합니다.

기존 `#article=...` 조문 주소는 질문 검색의 조문 창으로 연결해 호환성을 유지합니다. 새 열람 주소는 `#doc=...&item=...&date=...` 형식이며 브라우저의 뒤로/앞으로 이동을 지원합니다.

## 갱신

기존 문서 갱신 관리 체계를 그대로 사용합니다. 목차는 승인 색인에서 구성하며 문서 색인의 SHA-256을 검증합니다. 별도의 원문 복제본이나 수동 조문 목록을 관리하지 않습니다. `reader-model.js`는 시행일별 조문 선택과 실제 별표 판별, 기존 SOP 절 색인을 재사용합니다. 페이지 목차는 추출문 유무와 상관없이 모든 쪽을 보존합니다.

새 PDF 반영 시 목차와 연결 규정의 변화도 검토해야 합니다. 추출·색인 구조가 모호한 경우 PDF 원문을 기준으로 확인합니다. `node --test tests/*.test.mjs`와 `node tools/check-release.mjs`를 실행하고 실제 브라우저에서 조문·별표·SOP 이동을 확인합니다.


## 모바일 별표·서식

글 중심으로 원문을 확인한 별표는 텍스트를 기본으로 표시하고 원문 이미지를 접어서 대조합니다. 표·그림·서식은 WebP 원문 이미지를 기본으로 표시하며, 추출문은 별도로 펼쳐 볼 수 있습니다. 이미지에는 쪽과 용량을 표시하고 확대/화면 맞춤을 제공합니다. 각 이미지는 필요할 때 로드합니다. PDF 링크는 원본 확인용으로 유지합니다.

텍스트 우선 표시 검토는 `site/assets/annex-presentation.js`에 PDF 해시와 별표 번호로 묶습니다. 새 버전의 PDF에 이전 표시 판정을 자동 적용하지 않습니다. 새 버전은 우선 원문 이미지를 제공하고 내용을 확인한 뒤 텍스트 우선 여부를 추가합니다.

배포 시 `tools/build_page_previews.py`가 승인 색인의 실제 별표·별지 범위만 선택해 원본 PDF의 SHA-256을 확인하고 가로 1440px WebP를 생성합니다. `tools/verify_page_previews.py`로 페이지 누락·경로·해시·이미지 크기를 검사한 뒤 Pages에 배포합니다. 따라서 PDF 갱신 후 GitHub 배포 시 이미지도 자동 생성됩니다. 생성물은 Git에 저장하지 않습니다.

로컬 미리보기에서도 이미지를 보려면 `python -m pip install -r maintenance/preview-requirements.txt`를 설치한 후 `python tools/build_page_previews.py`를 실행합니다. Node가 PATH에 없다면 `NODE_BINARY`에 실행 파일 경로를 지정합니다. 이미지 파일이 없어도 텍스트와 PDF 원본 링크는 유지되며, 다른 PDF 버전의 이미지를 대체 표시하지 않습니다.


SOP 본문은 색 상자나 단계별 들여쓰기를 사용하지 않고 번호 열과 본문 열을 일정하게 정렬합니다. 원문에서 번호 다음 공백이 빠진 경우에도 줄 시작의 절차 번호를 구분해 표시합니다. 원문 OCR의 번호·띄어쓰기 자체를 수정하지 않으며 PDF 원문과 대조할 수 있습니다.


## SOP 본문의 그림·사진·도표

SOP는 별표뿐 아니라 모든 PDF 쪽의 화면용 이미지를 생성합니다. 그림·도표 목차에서는 PDF의 실제 그림·사진 영역과 표의 격자를 분석해 식별된 쪽을 모아 제공합니다. 탐지가 불완전한 경우에도 PDF 쪽 목차에서 모든 쪽의 원문 이미지를 볼 수 있습니다.

본문의 절을 열면 해당 절이 걸쳐 있는 PDF 쪽 중 그림·도표가 식별된 쪽을 함께 보여줍니다. 텍스트만 있는 절의 마지막 쪽과 다음 절 사이에 그림만 있는 쪽이 있으면 이 구간도 포함합니다. 한 쪽에 여러 절이 있으면 동일 원문 쪽을 각 절에서 대조할 수 있습니다. 마지막 절은 실제 텍스트의 끝까지만 연결하고 이후 참고자료를 임의로 해당 절의 내용으로 붙이지 않습니다.

단일 그림은 범례·주석을 포함한 영역을 발췌하고, 여러 쪽에 걸친 표는 해당 쪽 전체를 표시합니다. 발췌 그림은 화면에 맞게 보거나 확대할 수 있으며, 쪽 전체 보기로 대조할 수 있습니다. 이미지 속 내용은 AI로 설명하거나 텍스트 절차로 재해석하지 않습니다. 기존 절 주소와 원문 텍스트는 유지합니다.

CI는 원본 PDF 해시별 이미지 디렉터리를 캐시해 화면만 수정할 때 불필요한 재렌더링을 줄입니다. 목록과 시각 자료 표시는 매번 현재 승인 색인과 원본 PDF로 다시 구성합니다.


## 본문 키워드 검색과 그림 발췌

상단의 본문 키워드 검색에서 현재 문서 또는 전체 수록 문서를 선택합니다. 제목 필터와 달리 실제 조문·별표·SOP 본문을 검색하며, 적용 기준일에 맞는 문서·조문만 대상으로 합니다. PDF 줄바꿈·공백 차이는 무시하는 문자 검색이고, 의미를 추론해 답변하는 기능은 아닙니다. 결과에서 위치와 발췌문을 확인하고 클릭해 해당 항목으로 이동하면 일치하는 문자를 강조합니다. 결과는 40개씩 더 볼 수 있으며, 이미지 안의 글자는 기존 추출문에 있는 범위에서 검색합니다.

SOP 시각 자료는 `tools/sop_visuals.py`에서 PDF의 실제 이미지·도형·격자와 텍스트 위치를 분석합니다. 단순 도형 수 기준은 사용하지 않습니다. 반복 배경·제목 띠·간지·목차를 제외하고, 그림에는 인접한 제목·주석·범례를 포함할 여백을 둡니다. 그림을 구성하는 가느다란 래스터 조각도 합쳐 다룹니다. 연속된 격자 표는 원문 전체 쪽을 유지하고, 서로 다른 사진이 연속되었다는 이유만으로 전체 쪽으로 바꾸지 않습니다.

검토된 제외 쪽과 예외 발췌 영역은 `maintenance/visual-overrides.json`에 원본 PDF SHA-256별로 저장합니다. 개정 PDF에 이전 페이지 번호와 영역을 자동 재사용하지 않습니다. 불확실한 경우에는 원문 전체 쪽에서 확인할 수 있습니다. 발췌 이미지마다 '쪽 전체 보기'를 제공하고 PDF 쪽 목차는 모든 쪽을 보존합니다. 발췌 이미지의 경계·픽셀 크기·파일 해시도 배포 전에 검증합니다.


## SOP 본문 목차 재생성

`tools/build_sop_structure.py`는 PDF 본문 글꼴 크기와 큰 번호 제목의 주된 서식을 비교하여 상위 제목 목록을 만듭니다. 목록은 PDF SHA-256에 연결되며, 새 PDF 배포 시 다시 생성합니다. 페이지 첫 문장이 제목처럼 보인다는 이유만으로 하위 번호를 상위 목차에 올리지 않습니다. `sop-index.js`는 검증된 원문 부분 문자열을 제목 위치에서 나누고 하위 항목은 상위 본문에 포함합니다. 종전 목차 주소는 alias로 해당 상위 항목에 연결하며, 새로 복원한 제목은 기존 번호와 충돌하지 않는 주소를 부여합니다. 회귀 검사에서 원문 문자 보존, 구제역 PDF254~255 묶음과 PDF256 경계, 빠졌던 PDF280의 23번 제목, ASF PDF168의 18번 제목을 확인합니다. 문서별 본문 키워드 검색도 같은 목차를 사용합니다.


SOP 본문 키워드 검색이 별표·별지 쪽에 일치하면 PDF 쪽만 열지 않고 해당 별표·서식 항목으로 연결합니다. 참고자료에 재수록된 고시의 별표·서식은 SOP 자체의 동일 번호와 혼동하지 않도록 원래 PDF 쪽으로 열립니다.


## 인용 문맥과 절별 그림 위치

읽기 화면의 인용 링크는 명시된 법령명을 기준으로 나열된 조문·항·호를 연결합니다. `같은 법 시행령`, `같은 조 제2항`, 괄호 속 인용 뒤의 원래 조문 문맥, PDF 줄바꿈과 페이지 경계를 구분합니다. 미수록 법령은 현재 문서의 같은 번호로 바꿔 연결하지 않습니다. `npm run audit:reading-links`는 적용 기준일에 수록된 모든 문서의 인용 표기를 분류하고 대상 조문과 원문 위치를 검사합니다. 세 고시의 목적조항 21개는 별도의 도착 문서·조문 회귀 검사로 확인합니다.

구제역 SOP의 머리말만 있던 첫 항목은 첫 실제 본문인 정의에 합쳤습니다. 종전 주소는 유지합니다. 같은 PDF 쪽에 두 절이 있을 때 그림의 원본 좌표와 각 절 제목의 위치를 비교하여 해당 절에만 그림을 표시합니다. 괄호 안 혈청형 값의 줄바꿈이 하위 목록 번호로 바뀌지 않도록 구분합니다.
