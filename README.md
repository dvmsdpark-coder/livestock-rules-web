# 가축방역 규정 찾기

승인된 법령·고시·SOP에서 질문에 관련된 원문을 찾는 공개용 정적 웹앱입니다. 방문자 요청을 처리할 Python 서버, PostgreSQL, Docker, 자체 AI 서버가 필요하지 않습니다. GitHub Pages 또는 Cloudflare Pages에서 `site/` 폴더를 게시할 수 있습니다. 외부 AI 호출과 유료 서비스는 사용하지 않습니다.

## 현재 자료와 기능

가축전염병 예방법·시행령·시행규칙, 구제역·조류인플루엔자·아프리카돼지열병의 방역실시요령 및 SOP를 합쳐 승인본 9종(총 1,507쪽)을 포함합니다.

- 질문한 용어의 정의와 정확한 조문 제목·번호·항·호 검색
- 질문과 관련된 항목을 우선 표시하고, 같은 조문의 페이지는 묶어서 전체 원문 제공
- 확인 가능한 법·시행령·시행규칙 인용 링크, 고유하게 대조된 위임 문구 링크, 역방향 인용 목록
- 개별 조문의 시행 예정일을 반영한 현재·미래 조문 분리
- 3개 질병의 신고 기관·이동제한 해제·발생농장 소독 절차 검색
- ‘방역대·방역구역’을 방역지역의 개념·설정에 관한 검색으로 연결
- 기준일·질병·문서 종류 필터, SOP 백신접종·미접종 유형 구분
- 여러 쪽에 걸친 조건과 원문 PDF 페이지 연결, 별표·별지 번호 검색
- Web Worker에서 브라우저 검색, 문서 색인 SHA-256 검증

질문은 외부 AI로 전송하지 않습니다. 임의의 모든 자연어를 이해하는 모델은 아니며, 등록 문서 밖의 근거나 공식 유권해석을 생성하지 않습니다. 자동시험 통과가 전문가의 법령 해석 정확성 평가를 대신하지 않습니다.

## 실행과 시험

Node.js 22 이상에서:

```sh
npm test
node tools/serve.mjs
```

브라우저에서 `http://localhost:4173`을 엽니다. 이는 제작 중 미리보기용이며, 실제 방문자는 배포된 GitHub Pages 주소를 사용하므로 개인 PC가 켜져 있을 필요가 없습니다.

## GitHub Pages 배포

1. `livestock-rules-web`이라는 공개 저장소를 만들고 이 폴더의 내용을 올립니다. 개인 백업과 기존 Docker 프로젝트 전체를 올리지 마세요.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Test and publish search site**에서 실행합니다. 이후 `main` 갱신 시 자동시험을 통과한 경우에만 게시합니다.
4. 게시 주소: `https://<GitHub계정>.github.io/livestock-rules-web/`.

Cloudflare Pages를 사용하는 경우 Build command는 비워두고, 출력 디렉터리를 `site`로 설정합니다. GitHub Pages와 둘 다 사용할 필요는 없습니다. 커스텀 도메인 구매도 필수가 아닙니다.

## 문서 갱신

기존 Docker 앱은 문서 등록·검토 작업 공간으로 당분간 보존합니다. 승인 이후 `tools/export_approved.py`와 같은 폴더에 `tools/supplemental.py`를 함께 두고 내보내기 스크립트를 기존 API 컨테이너 내부에서 실행해 공개 스냅샷 ZIP을 생성합니다. 출력은 **바이너리 ZIP**이므로 텍스트 리디렉션을 사용하지 말고 Python `subprocess.run(..., stdout=파일)`로 저장합니다. 생성한 ZIP의 `data/`, `pdf/`를 `site/`에 반영하되 철회 문서의 이전 공개 파일이 남지 않도록 두 폴더를 새 스냅샷으로 교체하고 `npm test` 후 게시합니다.

내보내기는 DB를 읽기 전용 트랜잭션으로 조회하며 미승인 문서·관리 메모·세션·원본 저장 경로·비밀 설정을 포함하지 않습니다. 관리자 화면은 공개본에 없습니다. 비어 있는 그림 페이지에 OCR 잡음이 있지만 원본 PDF에 제목이 있는 경우에는 원래 PDF 텍스트를 우선 사용합니다. 원본 PDF는 바꾸지 않습니다.

향후 Docker를 삭제하기 전에는 별도의 문서 갱신 도구를 마련하고 개인 백업의 DB·원본 PDF·승인 및 검토 기록을 보존해야 합니다. 공개본만으로 관리자 작업 기록을 복원할 수 없습니다.

## 자료의 날짜와 출처

문서별 시행·검색 기준일과 버전은 게시 데이터에 포함됩니다. 구제역 SOP의 검색 기준일 `2026-05-06`은 사용자 요청에 따라 파일명 날짜를 사용한 것이며 공식 시행일은 미확인입니다. 화면에 이 사실을 함께 표시합니다. 기준일 이전 버전이 등록되지 않았다면 과거 시점의 답변을 보장하지 않습니다.

법령·SOP 원문은 각 발행 기관의 자료입니다. 이 검색 화면은 정부 공식 서비스가 아닙니다. 재배포 조건과 최신 개정 여부는 원문 발행처 기준으로 확인해야 합니다. 저장소에는 별도 오픈소스 라이선스를 임의 부여하지 않았습니다.

AI·ASF SOP의 발행 연월은 각각 2025년 11월·2024년 12월입니다. 파일명의 2025-11-18·2024-12-09는 검색용 기준일이며 공식 시행일로 확정하지 않았습니다. ASF SOP PDF 205~281쪽의 과거 고시(2023년판)·WOAH 참고 번역문(2019년판)은 기본 검색에서 제외하고 전체 PDF에 보존합니다. 절차 범위는 `tools/supplemental.py`에서 원본 SHA-256에 묶어 검증하므로 다른 개정판에는 재사용되지 않습니다.

조문 연결은 등록된 문서와 적용 기준일 안에서만 작동합니다. 외부 법령, 대상이 없거나 여러 개여서 특정할 수 없는 위임 문구는 추측하여 연결하지 않습니다. 역방향 목록은 인용 관계이며 위임의 법적 범위나 우선순위를 확정하는 기능은 아닙니다. 일부 항목을 발췌해 보여주므로 전체 원문의 조건·예외를 함께 확인해야 합니다.

## 조문 단위 검색과 자동 평가

정의·조문 번호·검증된 SOP 절차 검색을 우선하고, 나머지 질문은 문서에서 추출한 조문 제목·정의 용어와 일상 표현 사전으로 검색합니다. 문서 전체의 흔한 단어 개수 대신 항·호별 관련성을 평가하고, 여러 대상이 질문에 있으면 해당 대상을 함께 포함하는 근거를 찾습니다. 관련 호를 발췌할 때 해당 항의 도입 조건도 함께 보존합니다. 문서 유형·질병·시행일 필터는 순위 계산 전에 적용합니다.

추가 검색은 생성형 AI의 의미 이해가 아닌 용어 기반 검색입니다. 오탈자·새로운 표현·복합 예외 질문을 모두 해결하지는 못합니다. 일반 검색에는 등록된 법령·고시와 SOP 후보를 사용하며, SOP 후보는 검증된 절차 답변과 구분합니다. 전체 검색 실패가 규정 부존재를 뜻하지 않습니다.

- `npm test`: 기존 검색, 원문 보존, 질병 분리, 시행일, 검색 진단, 조문 링크 등의 회귀 검사.
- `npm run evaluate`: 독립 기대 조문을 둔 자연어 질문과 모든 현행 법령·고시의 조문 번호·제목을 점검하고 `docs/search-evaluation.json`에 결과를 기록합니다.
- 자연어 지표는 **기대 조문이 상위 6개 조문에 존재하는지**를 측정합니다. 첫 번째 결과의 정답률이나 모든 조건의 완전성을 뜻하지 않습니다.
- 조문 번호·제목 검사는 구조적 도달성 검사이며 자연어 질문 정확도와 따로 집계합니다.
- GitHub Actions에서 시험 또는 평가가 실패하면 공개 배포를 진행하지 않습니다. 실행별 평가 보고서를 Actions 산출물로 보존합니다.

질문 예시는 `tests/fixtures/questions.json`에서 관리합니다. 실제 사용 중 발견한 실패는 예시와 기대 조문을 추가한 뒤 수정하되, 이용자가 검색어를 전부 만들어야 하는 방식으로 운영하지 않습니다. 문서 개정 시 기대 조문의 존속·개정 여부와 자연어 예시의 전문가 검토는 별도로 필요합니다.

### SOP 본문 절·항목 검색

SOP 전용 검색은 승인된 본문 조각에서 절 제목과 번호 항목을 추출합니다. 같은 항목이 다음 PDF 페이지로 이어지면 원문 부분을 함께 보존하고, 절 전체를 별도로 펼쳐볼 수 있습니다. SOP 본문 용어도 검색어 사전에 포함합니다. 이는 개별 신고·소독 등 검토된 절차 외에 야생동물·시료채취·방역시설 등 상세 항목을 찾기 위한 검색 기능이며, 해당 절차의 법률 해석이나 완전성을 확정하지 않습니다.

목차, 간지·공백, 본문이 아닌 표·그림·서식, 참고용 재수록 법령은 일반 SOP 텍스트 검색과 구분합니다. 원문 PDF와 기존 별표·서식 검색은 보존합니다. 자동 절 구분은 PDF 추출 상태에 영향을 받으며, 모든 제목·표·그림의 의미를 검증한 것은 아닙니다. 별도 SOP 질문 표본 15개는 기대 절 제목·PDF 페이지·기본 표시를 검증하고, 구제역의 두 백신접종 유형과 야생조류의 항원 확인/고병원성 확진 단계를 구분해 검사합니다.

SOP 검색은 절 제목이 정확히 일치하면 그 절에 한정합니다. 일반 조치 질문에서는 질병 소개·정의 등 배경 절을 제외하고, 최고 관련도와 차이가 큰 절로 결과 수를 채우지 않습니다. 추가 후보는 본문 제목과의 일치 정도에 따라 기본 표시와 접힌 근거로 구분합니다. 제목의 숫자·공백·정중한 요청 표현을 정규화하며, '확진 시'와 '확진시'는 같은 검색 의도로 처리합니다. 별도 10개 정밀도 표본은 기대 절의 존재뿐 아니라 무관한 절이 기본 표시되지 않는지도 평가합니다. 표본 밖 임의 질문에 대한 정밀도를 보장하는 수치는 아닙니다.

### 문서별 근거와 연결 점검

검색 결과 상단의 '문서별 근거 함께 보기'에서 검색된 법률·시행령·시행규칙·고시·SOP를 구분해 확인합니다. 이는 검색된 근거 목록이며, 모든 상하위 규정이 빠짐없이 연결되었거나 법률 해석상 정합성이 확정되었다는 표시가 아닙니다. 문서 종류 필터가 SOP이면 법령은 함께 검색되지 않음을 표시합니다.

신고는 법 제11조의 신고 의무·신고기관, 시행규칙 제13조의 신고방법·신고사항·접수후조치, 질병별 고시와 SOP의 현장 절차를 나누어 확인합니다. '어디에' 외에 '신고 방법/절차/신고사항' 질문도 같은 근거에 연결합니다. 조문 번호·정확한 제목 검색은 일반 절차 분류보다 우선합니다.

`npm run audit:links`는 등록된 현재 자료에서 해석기가 연결한 인용의 대상 조문·항·호 유효성과 세 질병의 신고 근거 누락을 점검하고, SOP 검색 기준일보다 후속인 고시를 별도 검토 목록에 기록합니다. 외부 법령·해석하지 못한 인용, 개정 전후 문구의 의미상 충돌은 자동 확정하지 않습니다. 결과는 `docs/REGULATION_LINKS.md`와 `docs/regulation-links.json`에 남기며 GitHub Actions에서도 실행합니다.

### 생계안정·소득안정 지원 검색

'소득안정자금/지원금'과 '소득안정비용', '생계안정자금/생계비'와 '생계안정비용'의 표현 차이를 검색어로 연결하고, 해당 지원 질문에서 '지급/지원'을 검색에 함께 사용합니다. 지급이 보장된다는 뜻으로 바꾸어 설명하지 않습니다. 지원 대상·제외 조건을 호 하나로 분리하지 않고 해당 항의 원문과 함께 보여줍니다.

생계안정은 법 제49조제1항과 시행령 제12조, 소득안정은 법 제49조제2항과 시행령 제12조의2를 각각 검색하며, 법 제49조제3항의 위임 근거도 함께 표시합니다. 한 제도를 검색했을 때 다른 제도의 법률 항이 섞이지 않는지 검사합니다. 생계안정비용 상한을 발췌할 때에는 '제2항에도 불구하고'라는 별도 상향 조정 조항도 함께 보존합니다. 이는 등록 PDF의 해당 기준일 문구를 검색한 결과이며, 세부 지원 고시나 개별 지급 결정을 대신하지 않습니다.
